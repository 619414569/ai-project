# 登录按钮返回 403

## 原始提报

- 页面：`/login?redirect=/`
- 账号：`chyong`
- 操作：输入默认密码并点击“登录”
- 现象：页面提示 403，未进入工作台

## 排查记录

- 不带 `Origin` 的命令行请求通过前端代理和后端直连均返回 200。
- 浏览器从 `http://127.0.0.1:5174` 发起请求时稳定返回 403。
- 后端默认 CORS 仅允许 `http://localhost` 和 `http://localhost:5173`，没有覆盖 `127.0.0.1` 及 Vite 端口占用后的自动递增端口。
- 前端同时存在公开登录请求继承本地旧 JWT 的风险，作为同一认证入口的附加缺陷一并修复。

## 修复

- 后端改用 `allowed-origin-patterns`，默认允许 `localhost` 和 `127.0.0.1` 的本地开发端口，外部域名仍被拒绝。
- 登录动作开始时清除旧 token 和旧用户资料。
- 登录接口明确禁止附加 `Authorization` 请求头。
- 其他受保护接口继续附加当前 token。

## 防复发校验

- `auth-request.test.ts` 验证本地存在 stale token 时登录请求仍不使用该 token。
- 验证受保护接口继续携带 token，无 token 时不生成认证头。
- `SecurityConfigTest` 验证 `http://127.0.0.1:5174` 和 `http://localhost:5173` 被允许，外部来源被拒绝。
- 发布前使用 `chyong/admin123` 从登录页完成一次真实登录，并确认 `/auth/me` 与工作台数据加载成功。

## 2026-10-14 复发记录

- 环境：公网 Docker 部署，入口 `http://101.43.127.111:1888`。
- 影响：`dcy`、`yf`、`zls`、`xqx` 四名用户在浏览器登录均返回 HTTP 403，响应正文为 `Invalid CORS request`。
- 对照：相同账号密码不携带 `Origin` 时返回 200；携带 `Origin: http://101.43.127.111` 时返回 200；携带真实来源 `Origin: http://101.43.127.111:1888` 时返回 403。
- 根因：Nginx 使用 `proxy_set_header Host $host`，该变量不保留非标准公网端口。Spring 收到的 Host 为 `101.43.127.111`，与浏览器 Origin 中的 `101.43.127.111:1888` 不一致，将同源请求误判为跨域请求并按 CORS 白名单拒绝。
- 首次修复遗漏：此前只覆盖了本地 Vite 动态端口的 CORS 场景，公网验收只验证首页、健康检查和不带浏览器 Origin 的命令行登录，没有验证非标准端口下的真实浏览器同源登录。
- 修复方案：Nginx API 代理改为传递 `$http_host`，同时补充 `X-Forwarded-Host` 和 `X-Forwarded-Port`，完整保留外部主机与端口。
- 新增回归：`nginx-proxy.test.ts` 固定校验生产 Nginx 不得再使用会丢失端口的 `$host`；目标服务器必须从公网以真实 Origin 验证四名用户登录及登录后的 `/auth/me`。

## 复发修复验证

- 2026-10-14 09:24 +08:00，本地前端 9 项单元测试、TypeScript 检查和生产构建全部通过。
- 目标服务器重新构建并替换前端容器，线上 `nginx -T` 显示 Host、X-Forwarded-Host 和 X-Forwarded-Port 均保留公网端口，前端及其余五个长期容器全部为 `healthy`。
- 从部署电脑携带真实 `Origin: http://101.43.127.111:1888`，分别使用 `dcy`、`yf`、`zls`、`xqx` 登录；四次登录和随后 `/api/v1/auth/me` 均返回 200，用户名逐一匹配，`passwordChangeRequired=true`。
- 验证过程中不输出、不记录 JWT，数据库和后端服务未重启。
