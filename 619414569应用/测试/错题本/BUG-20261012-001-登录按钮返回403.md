# 登录按钮返回 403

## 原始提报

- 页面：`/login?redirect=/`
- 账号：`chyong`
- 操作：输入默认密码并点击“登录”
- 现象：页面提示 403，未进入工作台

## 排查记录

- 不带 `Origin` 的命令行请求通过前端代理和后端直连均返回 200。
- 浏览器从 `http://127.0.0.1:5174` 发起请求时稳定返回 403。
- 后端默认 CORS 仅允许 `http://localhost` 和 `http://localhost:5173`，没有覆盖 `127.0.0.1` 及 Vite 端口占用后的自动递增端口。
- 前端同时存在公开登录请求继承本地旧 JWT 的风险，作为同一认证入口的附加缺陷一并修复。

## 修复

- 后端改用 `allowed-origin-patterns`，默认允许 `localhost` 和 `127.0.0.1` 的本地开发端口，外部域名仍被拒绝。
- 登录动作开始时清除旧 token 和旧用户资料。
- 登录接口明确禁止附加 `Authorization` 请求头。
- 其他受保护接口继续附加当前 token。

## 防复发校验

- `auth-request.test.ts` 验证本地存在 stale token 时登录请求仍不使用该 token。
- 验证受保护接口继续携带 token，无 token 时不生成认证头。
- `SecurityConfigTest` 验证 `http://127.0.0.1:5174` 和 `http://localhost:5173` 被允许，外部来源被拒绝。
- 发布前使用 `chyong/admin123` 从登录页完成一次真实登录，并确认 `/auth/me` 与工作台数据加载成功。
