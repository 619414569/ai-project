# v1.0 发布环境与目录迁移失败

## 原始报错

- 直接移动包含 `node_modules` 的旧应用目录时，Windows 返回 `Could not find a part of the path`，后续清理缓存文件时返回 `Access denied`。
- 当前终端未将 `npm`、`mvn` 加入 `PATH`，分别返回 `The term 'npm' is not recognized` 和 `The term 'mvn' is not recognized`。
- 离线安装缺少 `@types/node` 包，返回 `ERR_PNPM_NO_OFFLINE_TARBALL`；沙箱内访问 npm registry 返回 `ECONNREFUSED`。
- Node 测试及 Vite 构建在受限沙箱内创建子进程时返回 `spawn EPERM`。
- Maven 在受限沙箱内写入用户依赖缓存时返回 `.m2/repository/... AccessDeniedException`。
- 直接执行 `git push origin main` 时，当前网络无法连接 `github.com:443`；直连和清空无效代理后均超时。
- 首次使用 Git Data API 上传时，PowerShell 正则中的反斜杠被命令封装层转义，解析 `git ls-tree` 失败并主动中止。
- 首次创建注释标签时，GitHub Tag API 规范化 tagger 时区后生成的对象 SHA 与本地 `+0800` 标签不同，标签引用校验主动中止。
- 改用 UTC tagger 后，Tag API 返回的名称、消息、目标、tagger 和时间均与本地一致，但内部 tag object SHA 仍不同，标签引用再次主动中止。

## 根因

- 将可再生成的前端依赖缓存和源码一起移动，触发 Windows 深层路径、链接及文件占用问题。
- 发布终端使用隔离工具链，工具未加入系统级 `PATH`，网络、子进程和用户目录写入也受沙箱控制。
- 当前网络允许访问 `api.github.com:443` 和 `ssh.github.com:443`，但阻止 `github.com:443`，且本机没有 GitHub SSH 公钥。
- 首次 API 脚本对跨命令封装的正则转义存在错误；失败发生在第一条 tree 记录，未更新任何远程引用。
- GitHub Tag API 将 tagger 日期规范化为 UTC；标签名称、消息、目标提交、tagger 姓名和邮箱均一致，但 Git 对象内的时区文本不同会改变 SHA。
- Tag API 不保证其注释标签对象与本地 `git tag -a` 的底层序列化逐字节一致，因此不能用本地 tag object SHA 作为 REST 发布门禁。
- 这些问题发生在发布执行环境，不是应用代码或测试断言失败。

## 修复

- 只迁移 Git 跟踪文件和业务源码，`node_modules`、`.vite`、`dist`、`target` 均不进入 Git；旧本地缓存目录由仓库根 `.gitignore` 排除。
- 使用已定位的 Node、Maven 和 JDK 绝对路径执行发布校验。
- 依赖下载、Node 子进程和 Maven 本地仓库访问在明确授权的环境中执行。
- 保持项目原有 npm 交付方式，不提交本地工具临时生成的 pnpm 工作区文件。
- HTTPS Git 通道不可达时，使用 GitHub 官方 Git Data API；更新引用前必须确认远程父提交一致，并逐项验证 blob、tree、commit SHA 与本地完全相同。
- API tree 记录按制表符和空格分段解析，不再依赖跨命令封装的反斜杠正则。
- 通过 REST API 发布且注释标签对象无法保持 SHA 一致时，改用标准轻量标签，令本地和远程 `refs/tags/v1.0` 直接指向同一个已验证提交。

## 防复发校验

- 对原 `脚手架` 下 73 个 Git 跟踪文件逐项映射检查，新应用目录缺失数为 0。
- 前端 8 项测试、TypeScript 检查和 Vite 生产构建全部通过。
- 后端 Maven `clean package` 识别版本 `1.0.0`，10 项测试全部通过并生成新 JAR。
- GitHub API 生成的主体提交 `419e11e` 和日志提交 `df00ba2` 均与本地 SHA 完全一致，远程引用只允许非强制快进。
- 发布前再次运行错题本 `--release` 门禁和 `git diff --check`。

## 复发记录

### 2026-10-12 脚手架恢复后的前端缓存失效

- 现象：恢复 `脚手架` 源码后执行前端类型检查，终端返回 `'vue-tsc' is not recognized`；离线重建依赖时 pnpm 返回 `ERR_PNPM_IGNORED_BUILDS`。
- 原因：历史残留的 `node_modules` 只有部分缓存，没有完整的命令链接；新版 pnpm 对依赖构建脚本增加了非交互审批提示。
- 处理：使用现有包缓存离线重建 `node_modules`，随后单独执行类型检查和 Vite 生产构建，二者均通过。
- 防复发：从 Git 恢复或迁移项目后不得复用残缺依赖目录；验证时先重建被忽略的本地依赖，再执行类型检查和构建，缓存不得提交到仓库。

### 2026-10-12 Git Data API 缺失 blob 判定错误

- 现象：通过 Git Data API 同步目录调整时，只上传了 1 个新 blob，创建 tree 返回 `422 tree.sha ... is not a valid blob`。
- 原因：同步脚本对有序字典执行 `Group-Object sha` 时未正确读取属性，错误地把 14 个新 blob 合并为一组。
- 处理：tree 创建前主动中止，远端 `main` 未改变；改用显式 SHA 哈希表去重，并在更新引用前逐个校验 blob、tree、commit SHA。
- 后续预检：首次修正脚本又因手工填写错误的完整提交 SHA 而在本地中止，远端仍未改变；提交列表已改为从 `remoteBase..HEAD` 动态读取。
- 防复发：不得依赖 PowerShell 对字典属性的隐式适配完成 Git 对象分组，也不得手工抄写待同步提交 SHA；上传数量必须与基线差异统计一致，任一对象缺失或 SHA 不一致都禁止更新远端引用。

### 2026-10-12 GitHub 提交消息末尾换行丢失

- 现象：16 个新 blob 和首个 tree SHA 均与本地一致，但 Commit API 返回的提交 SHA 与本地不同。
- 原因：同步脚本对提交消息执行了 `TrimEnd`，删除了 Git 原始提交末尾的换行；GitHub Commit API 按传入消息原样生成对象，因此底层提交对象字节及 SHA 不同。API 返回时间使用 UTC 展示，但哈希枚举确认原始对象仍保留本地 `+0800` 时区。
- 处理：远端引用更新前主动中止；改为从本地原始 commit 对象提取包含末尾换行的完整消息，再重新创建并校验远端提交。
- 防复发：通过 Git Data API 创建提交时，不得对提交消息执行裁剪或换行规范化；只有 tree、父提交、作者、邮箱、时间、消息及最终 SHA 全部一致时才能更新分支引用。

### 2026-10-13 原型校验命令转义失败

- 现象：使用 PowerShell 内联执行包含 JavaScript 正则的校验命令时，PowerShell 在执行 Node.js 前返回 `ParserError: Missing type name after '['`。
- 原因：多层命令封装错误解释了 JavaScript 正则中的引号和方括号。
- 处理：原型文件未被修改；将校验逻辑固化为 `原型/validate-prototype.mjs`，避免跨 Shell 内联转义。
- 防复发：包含正则或多层引号的校验逻辑必须写入可版本化脚本，再以文件方式执行，不得拼接到 PowerShell 内联命令中。

### 2026-10-13 Edge 截图落盘与移动视口误判

- 现象：Edge 无头截图命令退出后立即检查文件，首次返回文件不存在；随后文件才出现在目标目录。生成的 390px 截图中，顶部退出按钮和卡片右侧同时被裁切。
- 原因：Windows 下 Edge 截图文件存在异步落盘窗口；同时命令行 `--window-size` 受到浏览器最小窗口宽度影响，截图画布宽度小于实际页面布局视口，不能作为移动端溢出的可靠证据。
- 处理：截图检查增加有界等待，并使用浏览器调试协议或等效工具精确设置移动布局视口；原型顶部栏补充品牌区收缩、操作区固定和窄屏字号/间距约束。
- 防复发：截图命令结束后必须等待目标文件稳定存在再读取；响应式验收须同时确认截图画布与布局视口尺寸一致，页面多处右边界同步被裁切时优先排查截图工具，而不是直接判定为页面缺陷。

### 2026-10-14 GitHub DNS 与内联正则转义复发

- 现象：检查近期修改同步状态时，`git fetch origin --prune` 返回 `Could not resolve host: github.com`；随后经 SSH 在服务器调用 GitHub API 时，内联 `sed` 正则又被本机 PowerShell 提前解析并返回 `ParserError: Missing type name after '['`。
- 影响：两次失败均为只读检查，本地和远端引用都未改变。
- 处理：停止使用跨 PowerShell、SSH 和 POSIX Shell 的内联正则，改为从服务器只读取 GitHub API 响应开头，确认远端 `main` 为 `649613879206b7665b615b0612b6beb8063cd490`，与本地 `HEAD` 一致。
- 防复发：复杂解析继续固化为版本化脚本；GitHub HTTPS/DNS 不可用时，只读状态核对可走已连接服务器的 API，提交与推送仍须在人工验收口令和发布门禁通过后执行。

### 2026-10-14 当前会话工具链 PATH 缺失

- 现象：V1.1 门禁直接执行 `npm test`、`npm run typecheck` 和 `mvn test` 时，当前 PowerShell 会话返回命令不存在；错误发生在测试启动前，不代表测试用例失败。
- 原因：本机仅将 Codex 自带的 `node.exe` 加入 PATH，未注册全局 npm 和 Maven。
- 处理：前端改为通过该 Node 直接调用项目内测试、`vue-tsc` 和 Vite 入口；后端以同一代码版本已完成的服务器 Docker 构建阶段 Maven 测试结果为准。
- 防复发：本机门禁先检查工具可用性；项目内依赖已安装时使用明确的 Node 模块入口，Maven 不可用时不得打印本地测试通过，必须引用同一代码版本的容器构建测试证据。

### 2026-10-14 沙箱禁止 Node 创建测试与构建子进程

- 现象：通过明确 Node 路径执行测试和 Vite 构建时，Node 测试运行器及 esbuild 均返回 `Error: spawn EPERM`；TypeScript 检查因不需要同类子进程而正常通过。
- 原因：受限执行环境禁止创建测试工作进程和 esbuild 子进程，与源码、依赖完整性无关。
- 处理：在允许项目测试子进程的受控会话中重跑相同命令，13 项前端测试全部通过，Vite 完成 1689 个模块的生产构建。
- 防复发：遇到 `spawn EPERM` 时先区分沙箱权限与测试断言失败；仅在授权的受控会话中重跑必要命令，并保留初次错误和最终结果。

### 2026-10-14 Git 中文路径边界检查假阳性

- 现象：使用 `git diff --name-only` 的默认输出检查目录前缀时，所有 `619414569应用/**` 文件都被误报为越界。
- 原因：Git 默认启用 `core.quotePath`，中文目录被输出为带引号的八进制转义文本，无法直接与中文前缀比较；对 `脚手架/**` 的独立状态查询始终为空。
- 处理：边界检查显式使用 `git -c core.quotePath=false status --short` 输出真实中文路径，并继续单独查询受保护目录。
- 防复发：任何依赖 Git 路径文本的自动校验都必须关闭 `quotePath` 或使用 NUL 分隔的机器可读格式，不能比较 Git 的展示转义字符串。

### 2026-10-14 新增 Markdown 的暂存空白检查遗漏

- 现象：两份新版本日志用行尾双空格表示 Markdown 强制换行，暂存后的 `git diff --cached --check` 报告四处 `trailing whitespace`。
- 原因：此前只执行 `git diff --check`，未跟踪的新文件不会进入普通工作区差异检查，因此直到暂存后才暴露。
- 处理：删除行尾双空格，以普通换行展示元数据；重新暂存并执行缓存区空白检查。
- 防复发：发布门禁同时执行工作区和暂存区的 `diff --check`；新增文件必须在暂存后再做一次空白检查。

### 2026-10-14 V1.1 推送时 GitHub HTTPS 通道再次不可达

- 现象：V1.1 两次本地提交完成后，`git push origin main` 没有更新远端；`git ls-remote` 明确返回 `Failed to connect to github.com port 443`。清除当前进程中的无效代理后仍超时。
- 中转排查：生产服务器的 `deploy` 用户执行 sudo 需要密码，固定部署密钥不允许 root 登录；服务器到 GitHub HTTPS 同样超时。部署密钥也未在 GitHub 注册，SSH 推送返回 `Permission denied (publickey)`。
- 网络定位：系统 curl 可访问部分 GitHub 官方前端，但 Git for Windows 的 libcurl 直连相同地址仍在 TCP 连接阶段超时；所有失败均发生在远端引用更新前，本地提交保持完整。
- 处理：新增 `scripts/push-github-data-api.ps1`，复用 Git 凭据管理器且不输出令牌，通过可达的 `api.github.com` 上传缺失 blob，逐项验证 blob、tree、commit SHA，并仅在远端父提交与本地历史一致时非强制快进 `main`。
- 防复发：普通 Git HTTPS 不可达时直接使用版本化 API 脚本，不再重复尝试服务器 sudo、root 或未授权 SSH 密钥；远端引用更新后必须再次读取 GitHub ref 并与本地 `HEAD` 精确比较。
- 首次执行回退脚本时，跨行书写的 `.Split()` 被 PowerShell 当作命令调用并在任何 API 写操作前中止；三处方法调用已改为在完整括号表达式后直接调用，并重新执行脚本语法与运行验证。
- 修正后两次串行上传 40 个 blob 超出命令托管窗口，遗留的 PowerShell 子进程随后退出且远端 `main` 仍为 `96c1ffc`。脚本改为最多 8 路并发上传 blob，并在 blob 和每个提交校验后输出进度，避免无输出长任务被误判为完成。
- 并发上传后 40 个 blob SHA 全部一致，但首个 tree 因 `git ls-tree` 默认转义中文路径而产生 SHA 不匹配，脚本在更新引用前按设计中止。tree 枚举现显式使用 `core.quotePath=false`，确保 API 收到真实 UTF-8 路径；错误的临时 tree 未被任何提交或分支引用。

### 2026-10-15 沙箱禁止创建 Git 索引锁

- 现象：新增生产用户通过验收后，首次执行 `git add` 和 `git commit` 均返回 `Unable to create '.git/index.lock': Permission denied`。
- 影响：Git 在写入索引前中止，没有文件被暂存，也没有生成部分提交；应用、生产数据库和远端分支均未改变。
- 处理：确认工作区仅包含已验收文件且 `脚手架/**` 无变更，追加本记录并重新执行发布门禁，再通过受控权限完成 Git 索引写入。
- 防复发：提交前先确认执行环境对 `.git` 的写权限；若受限环境阻止索引锁，只申请限定于当前仓库 Git 操作的权限，不修改文件系统权限或绕过仓库边界。

### 2026-10-15 受限环境无法使用 SSH 私钥签名

- 现象：首次通过固定主机别名向生产 PostgreSQL 传入备注脚本时，SSH 长时间无输出；中止后以 `BatchMode` 诊断显示服务器接受公钥，但客户端无法完成签名并返回 `Permission denied`。
- 影响：失败发生在远程命令和 SQL 执行前，生产数据库没有变更。
- 原因：受限执行环境无法访问 SSH Agent 或私钥签名能力；普通交互模式因此等待认证输入而没有及时失败。
- 处理：后续连接统一增加 `BatchMode=yes` 和 `ConnectTimeout=10`，在获准的受控权限通道使用同一专用密钥；连接探针成功后，备注脚本回滚演练、正式执行和只读复核全部通过。
- 防复发：自动化 SSH 必须使用批处理模式和明确连接超时；先运行无副作用连接探针，再执行数据库事务，禁止让认证提示以无限等待方式阻塞发布任务。

### 2026-10-15 PowerShell 路径与行号拼接解析失败

- 现象：本地空白检查输出 `"$file:$($_.LineNumber)"` 时，PowerShell 返回 `Variable reference is not valid`，命令在读取文件前停止。
- 影响：仅该次只读检查未执行，文件、生产数据库和 Git 状态均未改变。
- 原因：PowerShell 将变量名后的冒号视为作用域语法的一部分，未能按预期把它识别为普通分隔符。
- 处理：变量引用改为边界明确的 `"${file}:$($_.LineNumber)"` 后重新执行检查。
- 防复发：PowerShell 字符串内的变量后紧跟冒号、点号或其他可能参与标识符解析的字符时，统一使用 `${name}` 显式限定变量边界。

### 2026-10-15 临时 Excel 锁文件在检查期间消失

- 现象：工作区状态最初存在 `~$生产数据库全量导出_2026-10-15.xlsx`，后续一次性读取导出文件和锁文件属性时，`Get-Item` 报告锁文件路径不存在。
- 影响：临时锁文件由 Excel 自动管理，交付用的 `生产数据库全量导出_2026-10-15.xlsx` 仍完整存在，未发生业务文件删除或覆盖。
- 原因：用户关闭工作簿后 Excel 自动移除了临时锁文件，只读检查仍按较早状态假定其存在。
- 处理：确认 Git 状态中仅保留正式导出文件，不恢复、不提交临时锁文件。
- 防复发：检查 Office 临时锁文件时先使用 `Test-Path`，并将其视为瞬时状态；交付与版本控制只核对不以 `~$` 开头的正式文件。

### 2026-10-15 敏感信息检查使用了错误目录名

- 现象：备注 SQL 的敏感信息检查把实际目录 `数据` 写成 `data`，`rg` 因文件不存在返回退出码 2。
- 影响：该次检查没有读取 SQL，不能作为敏感信息检查证据；其他门禁和生产数据不受影响。
- 原因：手工拼写路径时混用了中文仓库目录名与英文习惯名称。
- 处理：改用实际文件路径 `619414569应用/数据/comment-production-database.sql` 重新执行，并区分 `rg` 的无匹配退出码 1 与执行错误退出码 2。
- 防复发：对已知文件执行门禁前先用 `Test-Path -LiteralPath` 验证路径；只有文件存在且扫描命令正常完成时才允许记录检查通过。

### 2026-10-15 规则文件静态校验误差

- 现象：首次校验 `规则/rules.md` 时发现版本元数据两行带 Markdown 强制换行空格；同时必备条款检查使用与正文不同的完整句子，误报“规则修改确认条款缺失”。
- 影响：规则正文已包含修改确认要求，错误仅使静态校验失败；没有执行提交、推送或生产操作。
- 原因：新文档沿用了行尾双空格排版，检查器又把语义校验写成脆弱的逐字字符串匹配。
- 处理：删除行尾空格；必备条款改用正文中的稳定关键词组合校验，并重新执行 Markdown 和规则覆盖检查。
- 防复发：新增 Markdown 在未暂存时也要显式扫描行尾空白；治理文档校验应匹配稳定标题和关键术语，不依赖可正常改写的整句文案。

### 2026-10-15 合并前 GitHub fetch 连接被重置

- 现象：个人分支成功推送后执行 `git fetch origin main`，Git 返回 `Recv failure: Connection was reset`；同一 PowerShell 命令继续读取了本地缓存的 `origin/main`，导致命令整体退出码被后续成功语句覆盖。
- 影响：远端引用没有更新，本地尚未切换或修改 `main`；缓存的 `origin/main` 不能作为本次合并前远端核对证据。
- 原因：GitHub HTTPS 连接发生瞬时重置，同时组合命令没有在原生命令失败后立即检查 `$LASTEXITCODE`。
- 处理：停止合并，记录错误并将验收状态恢复为 `pending`；后续把 fetch 与引用比较放入遇错即停逻辑，fetch 成功后才允许使用刷新后的远端引用。
- 防复发：所有 Git 网络命令执行后必须立即断言 `$LASTEXITCODE -eq 0`，不得让后续只读命令覆盖失败状态，也不得使用失败 fetch 后的缓存引用完成合并门禁。
