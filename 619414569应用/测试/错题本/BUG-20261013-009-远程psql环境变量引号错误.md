# 远程 psql 环境变量引号错误

## 原始问题

远程执行数据重置时 PostgreSQL 返回：

```text
psql: error: connection to server on socket "/var/run/postgresql/.s.PGSQL.5432" failed:
FATAL: role "  -d" does not exist
```

## 根因

本机 PowerShell 在 SSH 命令发送前处理了 `$POSTGRES_USER` 和 `$POSTGRES_DB`，远程容器没有收到预期变量值，导致 `psql` 参数错位。

## 修复

- 使用已确认的数据库角色和数据库名作为独立 `psql` 参数，避免跨 PowerShell、SSH 和容器 shell 的多层变量展开。
- SQL 脚本启用 `\set ON_ERROR_STOP on` 并使用事务，首次连接失败时没有执行任何数据修改。
- 执行成功后轮换 JWT 密钥并恢复后端服务。

## 防复发校验

- 数据维护脚本必须启用 `ON_ERROR_STOP` 并包裹在事务中。
- 执行后直接查询用户、应用、合作关系和提交日志数量。
- 重启后端后再次查询，确认演示数据没有被重新写入。

## 2026-10-14 命令插值复发

- 在检查远端容器健康状态时，SSH 双引号参数中的 `$(docker inspect ...)` 再次被本机 PowerShell 提前解析，本机因没有 Docker 命令而报错。
- 该错误只影响等待循环；同一命令后续的远端 `docker compose ps` 和 `nginx -T` 正常执行，未修改服务器状态，也未影响已经健康的容器。
- 后续远程检查不再在 PowerShell 双引号字符串中使用 shell 命令替换；改用无命令替换的远端命令，或使用能阻止本机展开的参数传递方式。
- 本次已直接核对 `docker compose ps`，六个长期容器全部为 `healthy`，并通过独立公网请求验证服务状态。

## 2026-10-14 线上扫描命令再次复发

- 在 SSH 双引号参数中嵌套 `sh -c`、管道和条件语句时，误用反斜杠转义双引号；PowerShell 没有把反斜杠当作引号转义，导致远端命令被拆成本机命令，扫描未执行。
- 命令只包含只读检查，没有修改服务器；随后改用两个不含管道和条件语句的独立 `grep` 命令，均以无匹配状态退出，确认线上产物不含 `admin123` 和“默认密码”。
- 远程检查优先使用单一程序和简单参数；需要远端 shell 组合时，必须使用 PowerShell 能正确保留的单引号参数，并在执行前检查是否含 `$()`、管道或嵌套引号。

## 2026-10-14 HTTP 校验误报

- 首次登录回归使用 `Invoke-RestMethod` 时没有设置 `$ErrorActionPreference = 'Stop'`；`dcy/admin123` 返回 401 后脚本仍继续执行，并打印了错误的成功文案。
- 该命令只读取接口且登录失败，没有产生令牌或数据修改；错误文案未被计入测试结论。
- 修正后启用终止错误、显式检查 `accessToken` 和返回用户名，使用仍保持初始密码的 `zls` 完成登录和 `/auth/me` 回归，两项均返回 200。
- 后续 PowerShell HTTP 验收命令必须启用终止错误，并对关键响应字段做断言，禁止仅依赖命令尾部的固定成功输出。

## 2026-10-14 PowerShell 遍历结果管道语法错误

- 批量检查路径穿越载荷时，将 `foreach` 语句块直接接到管道，PowerShell 返回 `An empty pipe element is not allowed`，请求尚未执行。
- 修正为先将每次检查结果收集到数组，再由数组统一传给 `Format-Table`；重试后四个载荷均得到明确状态码。
- 复杂 PowerShell 控制语句不直接拼接尾部管道，先保存结构化结果再输出，避免语法错误遮蔽接口验证。

## 2026-10-15 新增生产用户时 SQL 引号解析失败

- 首次新增 `qhh`、`ytt` 时，在 PowerShell 双引号命令中使用反斜杠转义远端 `psql -c` 的 SQL；PowerShell 不识别该转义方式并在本机返回 `ParserError: Missing argument in parameter list`。
- 错误发生在 SSH 启动前，生产数据库没有执行任何语句或产生部分数据。
- 修正为通过 SSH 标准输入将 SQL 直接送入容器内 `psql`，并启用 `ON_ERROR_STOP` 和数据库事务，避免 PowerShell、SSH、远端 shell 与 SQL 四层引号嵌套。

## 2026-10-15 业务数据数量查询再次触发本机解析

- 首次复核业务数据数量时，将含 `COUNT(*)`、反斜杠和多层引号的 SQL 嵌入远程命令；PowerShell 在 SSH 启动前把 `*` 和 `\` 解析成本机命令，分别返回 `The term '*' is not recognized as a name of a cmdlet` 和 `The term '\' is not recognized as a name of a cmdlet`。
- 失败发生在本机命令解析阶段，只读 SQL 未发送到生产数据库，没有任何数据变更。
- 后续查询把 SQL 通过标准输入直接传给 `psql`，远程命令行只保留固定连接参数，不再使用 `psql -c` 嵌套 SQL。

## 2026-10-15 沙箱 SSH 同名包装程序拦截

- 使用未限定路径的 `ssh` 时，PowerShell 优先解析到 `C:\Users\ZhuanZ1\.sbx-denybin\ssh.bat`，仅返回 `off` 和 `exit /b 1`，查询没有连接服务器。
- 改用明确路径 `C:\Windows\System32\OpenSSH\ssh.exe`，并设置 `BatchMode=yes`、`ConnectTimeout=10`；只读查询成功，确认生产库有 3 个个人应用、0 个合作人关系和 0 条提交日志。
- 自动化远程验收先用 `Get-Command ssh -All` 核对可执行文件来源；受控环境中使用明确的 OpenSSH 路径和连接超时，避免同名包装程序或交互等待遮蔽结果。

## 2026-10-15 公网登录断言遗漏统一响应包装

- 重跑 `qhh`、`ytt` 公网登录验收时，首次脚本错误检查顶层 `accessToken`，而接口实际返回 `ApiResponse<LoginResponse>`，令牌位于 `data.accessToken`；HTTP 请求成功，但本地断言报“login response has no access token”。
- 该操作仅调用登录接口，没有修改用户、应用或其他业务数据；失败结果未计入验收结论。
- 根据后端 `ApiResponse` 和 `AuthController` 确认响应结构后，改为断言 `login.data.accessToken`、`me.data.username` 和 `me.data.passwordChangeRequired`；两名用户均通过公网回归。
