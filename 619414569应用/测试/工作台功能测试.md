# 工作台功能测试文档

## 1. 测试目标

验证工作台在脚手架技术栈上的功能、权限、数据持久化、构建和独立运行能力。所有 P0/P1 用例通过且不存在未关闭的阻断或严重缺陷，只能判定技术检查完成；项目负责人还必须单独输入 `本次验收通过`，才能确认最终验收通过。

## 2. 测试范围

- Spring Security JWT 登录、退出和持久化修改密码。
- 个人应用、其他成员共享应用、合作应用和合作人权限。
- 应用地址选填、补填、校验和跳转。
- 应用共享/独享、暂停/恢复和删除。
- 按用户展示和筛选代码提交记录。
- 版本更新日志按人员查询、按文件名倒序展示并在线预览 Markdown。
- 生产数据库表和字段备注完整、准确，元数据维护不改变业务数据。
- 前后端独立构建、Docker 镜像和 Compose 集成。
- 桌面端与移动端关键流程。

## 3. 测试环境

| 项目 | 要求 |

| Node.js | 22+ |

| 容器 | Docker Engine 24+、Compose v2 |
| 默认账号 | `admin` / `admin123` |

## 4. 验收规则

- P0、P1 用例必须全部通过。
- 自动化测试必须零失败、零跳过。
- 前后端生产构建必须成功。
- 未授权访问、越权修改和危险 URL 必须被拒绝。
- 测试结果必须记录实际输出；未执行项保持“未执行”或“阻塞”，不得记为通过。
- 自动化测试、构建、部署和回归通过不等同于最终验收通过，完成后状态保持“待人工验收确认”。
- 只有项目负责人单独输入完整口令 `本次验收通过`，才允许把验收状态改为 `accepted` 并按已验收代码提交、推送。
- 口令仅覆盖当时列明的变更范围；确认后的任何代码、配置、数据脚本或测试结论变更都会使验收失效，必须重新测试并再次确认。
