# AI 工作台 v1.1 服务器部署准备清单

- 应用版本：`1.1.0`
- 核对日期：`2026-10-13`
- 推荐方式：Docker Compose 一体化部署
- 项目目录：`619414569应用/`

## 1. 先确认部署方式

### 方案 A：Docker Compose 一体化部署（推荐）

服务器只需要提前安装 Docker Engine 和 Docker Compose。Java、Maven、Node.js、Nginx、PostgreSQL、Redis、RocketMQ 均由项目镜像提供，不需要安装到宿主机。

- [ ] Docker Engine `24+`
- [ ] Docker Compose `v2`
- [ ] Linux `x86_64`；ARM64 部署前已逐个确认基础镜像支持该架构
- [ ] 可执行 `docker compose version`
- [ ] 部署账号已加入 `docker` 用户组，或具备等效执行权限
- [ ] Docker 服务已设置为开机启动
- [ ] 服务器时间与时区已正确配置，建议启用 NTP
- [ ] 应用位于 `/opt/ai-workbench`、`/srv/ai-workbench` 或其他部署账号可写目录，生产环境建议使用 ASCII 路径

Compose 会启动以下容器：

| 容器 | 版本 |
| --- | --- |
| 前端 | Nginx `1.27-alpine` |
| 后端构建 | Maven `3.9.9` + Eclipse Temurin JDK `17` |
| 后端运行 | Eclipse Temurin JRE `17` |
| 数据库 | PostgreSQL `16-alpine` |
| 缓存 | Redis `7.4-alpine` |
| 消息 NameServer/Broker | RocketMQ `5.3.1` |

### 方案 B：应用容器 + 云上中间件

服务器仍只安装 Docker Engine 和 Docker Compose，但需提前申请并配置以下外部服务：

- [ ] PolarDB-PG 实例已创建，版本与 PostgreSQL 语法兼容
- [ ] 已创建业务库 `ai_scaffold`
- [ ] 数据库账号具备建表、建索引、增删改查权限，允许 Flyway 建表
- [ ] PolarDB 白名单允许后端服务器访问，默认端口为 `5432`
- [ ] Redis 实例已创建，建议与 Redis `7.4` 兼容
- [ ] Redis 密码和网络白名单已配置，默认端口为 `6379`
- [ ] RocketMQ `5.3.1` 服务已准备，后端可访问 NameServer `9876`
- [ ] 已按实际服务地址修改 Compose，不再启动本地 PostgreSQL、Redis、RocketMQ 服务

> 项目没有固定 PolarDB-PG 的云产品小版本。上线前必须在目标实例执行 Flyway V1、V2 迁移验证；本地兼容基线为 PostgreSQL 16。

### 方案 C：宿主机原生部署（不推荐）

只有明确不使用容器时，才需要提前安装：

- [ ] JDK `17`
- [ ] Maven `3.9.x`，当前容器使用 `3.9.9`
- [ ] Node.js `22`
- [ ] npm `10+`
- [ ] Nginx `1.27`
- [ ] PostgreSQL 16 或可兼容的 PolarDB-PG
- [ ] Redis `7.4`
- [ ] RocketMQ `5.3.1`

## 2. 服务器资源建议

以下为单机开发或小规模验收环境建议，不是代码硬限制：

- [ ] CPU：至少 `4` 核
- [ ] 内存：至少 `8 GB`；在服务器上同时构建镜像时建议 `12 GB+`
- [ ] 可用磁盘：至少 `30 GB`
- [ ] 文件系统支持 Docker volume 持久化
- [ ] 已规划数据库、Redis、RocketMQ 和日志的备份策略

## 3. 网络和软件源

如果在服务器执行 `docker compose up -d --build`，首次构建需要访问：

- [ ] Docker Hub，用于下载 PostgreSQL、Redis、RocketMQ、Maven、Temurin、Node 和 Nginx 镜像
- [ ] Maven Central，用于下载后端依赖
- [ ] npm Registry，用于下载前端依赖
- [ ] GitHub 或内部 Git 服务，用于获取项目代码
- [ ] DNS、HTTPS 代理和防火墙策略已验证

离线服务器应在联网构建机提前构建镜像，再通过 `docker save`/`docker load` 或内部镜像仓库传输，不应在离线服务器现场下载依赖。

> 前端已提交 `package-lock.json`，Docker 构建固定执行 `npm ci`，依赖版本由 lockfile 锁定。升级依赖后应同步提交更新后的 lockfile。

## 4. 端口和防火墙

| 端口 | 服务 | 建议开放范围 |
| --- | --- | --- |
| `80` | 前端 Nginx | 对用户开放，或仅向上层网关开放 |
| `443` | HTTPS | 当前项目未内置证书，建议由服务器网关或负载均衡终止 TLS |
| `8080` | Spring Boot API | 建议仅内网或仅前端 Nginx 可访问 |
| `5432` | PostgreSQL/PolarDB-PG | 仅后端可访问 |
| `6379` | Redis | 仅后端可访问 |
| `9876` | RocketMQ NameServer | 仅后端和 Broker 可访问 |
| `10911` | RocketMQ Broker | 仅业务服务可访问 |

- [ ] 公网仅开放必要的 `80/443`
- [ ] 数据库、缓存和消息端口未直接暴露到公网
- [ ] 域名解析和 HTTPS 证书已准备
- [ ] 反向代理上传大小、超时和请求头策略已确认

rootless Docker 或端口 `80` 已占用时，使用 `WEB_PORT=8088 sh scripts/deploy.sh`；脚本会将覆盖值持久写入 `.env`。防火墙和上层网关需同步开放或转发该端口。

## 5. 配置和密钥

首次执行 `sh scripts/deploy.sh` 会自动从 `.env.example` 创建 `.env`，随机生成数据库、Redis 和 JWT 等基础设施密钥，并保留产品约定的用户初始密码 `admin123`。也可以在部署前手工创建 `.env`，至少检查以下配置：

- [ ] `WEB_PORT`
- [ ] `BACKEND_PORT`
- [ ] `POSTGRES_DB`
- [ ] `POSTGRES_USER`
- [ ] `POSTGRES_PASSWORD` 已替换默认值
- [ ] `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`
- [ ] `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`
- [ ] `REDIS_HOST_PORT` 仅用于宿主机端口映射，与后端连接端口分开配置
- [ ] `ROCKETMQ_NAME_SERVER`
- [ ] `JWT_SECRET` 已替换为至少 32 位的高强度随机值
- [ ] `JWT_ACCESS_TOKEN_TTL`
- [ ] `DEMO_ADMIN_USERNAME` 已设为实际管理员账号
- [ ] `DEMO_ADMIN_PASSWORD` 为约定初始值 `admin123`；首次登录后已立即修改
- [ ] 正式数据环境已设置 `APP_DEMO_DATA_ENABLED=false`，避免重启时补回演示用户、应用和提交日志
- [ ] `提交日志` 目录存在且后端容器以只读方式挂载到 `/app/update-logs`
- [ ] `CORS_ALLOWED_ORIGINS` 只包含正式域名
- [ ] `BACKEND_URL` 指向前端容器可访问的后端地址

禁止将生产 `.env`、数据库密码、Redis 密码、JWT 密钥或证书私钥提交到 Git。
部署脚本会将 `.env` 权限设置为 `600`，并拒绝缺失密钥、短于 32 位的 JWT 密钥和默认基础设施口令。用户初始密码按产品要求保留为 `admin123`，由首次登录改密流程负责收敛。

## 9. 宿主机不需要安装的组件

采用推荐的 Docker Compose 方案时，以下组件无需提前安装到服务器宿主机：

- Java/JDK
- Maven
- Node.js/npm
- Nginx
- PostgreSQL
- Redis
- RocketMQ
- Flowable

这些组件均由容器镜像或 Spring Boot 应用依赖提供。服务器只需准备 Docker、配置文件、网络、存储和安全策略。
