# v1.0 发布环境与目录迁移失败

## 原始报错

- 直接移动包含 `node_modules` 的旧应用目录时，Windows 返回 `Could not find a part of the path`，后续清理缓存文件时返回 `Access denied`。
- 当前终端未将 `npm`、`mvn` 加入 `PATH`，分别返回 `The term 'npm' is not recognized` 和 `The term 'mvn' is not recognized`。
- 离线安装缺少 `@types/node` 包，返回 `ERR_PNPM_NO_OFFLINE_TARBALL`；沙箱内访问 npm registry 返回 `ECONNREFUSED`。
- Node 测试及 Vite 构建在受限沙箱内创建子进程时返回 `spawn EPERM`。
- Maven 在受限沙箱内写入用户依赖缓存时返回 `.m2/repository/... AccessDeniedException`。

## 根因

- 将可再生成的前端依赖缓存和源码一起移动，触发 Windows 深层路径、链接及文件占用问题。
- 发布终端使用隔离工具链，工具未加入系统级 `PATH`，网络、子进程和用户目录写入也受沙箱控制。
- 这些问题发生在发布执行环境，不是应用代码或测试断言失败。

## 修复

- 只迁移 Git 跟踪文件和业务源码，`node_modules`、`.vite`、`dist`、`target` 均不进入 Git；旧本地缓存目录由仓库根 `.gitignore` 排除。
- 使用已定位的 Node、Maven 和 JDK 绝对路径执行发布校验。
- 依赖下载、Node 子进程和 Maven 本地仓库访问在明确授权的环境中执行。
- 保持项目原有 npm 交付方式，不提交本地工具临时生成的 pnpm 工作区文件。

## 防复发校验

- 对原 `脚手架` 下 73 个 Git 跟踪文件逐项映射检查，新应用目录缺失数为 0。
- 前端 8 项测试、TypeScript 检查和 Vite 生产构建全部通过。
- 后端 Maven `clean package` 识别版本 `1.0.0`，10 项测试全部通过并生成新 JAR。
- 发布前再次运行错题本 `--release` 门禁和 `git diff --check`。
