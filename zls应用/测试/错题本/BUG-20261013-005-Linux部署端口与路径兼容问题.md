# Linux 部署端口与路径兼容问题

## 原始问题

- 仓库启用 `core.autocrlf=true` 时，部署脚本没有文件级 LF 约束，Windows 再次检出后可能以 CRLF 进入 Linux 发布包并出现 `/bin/sh^M` 或命令尾部 `\r` 错误。
- Compose 同时使用 `REDIS_PORT` 映射宿主机端口和配置后端连接端口。服务器为避让端口占用设置 `REDIS_PORT=16379` 后，Redis 容器仍监听 `6379`，后端却会连接 `redis:16379` 并启动失败。
- 独立容器文档直接使用 `host.docker.internal`，Linux Docker 默认不会像 Docker Desktop 一样自动提供该域名。

## 根因

- 应用目录没有 `.gitattributes` 固定 Linux 解释文件的换行格式。
- 将宿主机端口映射和 Docker 网络内服务端口视为同一个配置维度。
- 独立容器示例沿用了 Docker Desktop 的主机名约定，没有添加 Linux `host-gateway` 映射。

## 修复

- 在应用目录新增 `.gitattributes`，强制 Shell、Dockerfile、Compose、Nginx 模板和配置文件使用 LF。
- 新增 `REDIS_HOST_PORT` 专门控制宿主机映射；`REDIS_PORT` 只表示后端实际连接的服务端口。
- 部署脚本使用 POSIX Shell 语法，验证 Docker 正在运行 Linux 容器；`.env` 使用 `600` 权限，临时密钥文件在退出或中断时清理。
- rootless Docker 或端口冲突场景支持 `WEB_PORT=8088 sh scripts/deploy.sh`，覆盖值会持久写入 `.env`。
- Linux 独立容器命令显式增加 `--add-host=host.docker.internal:host-gateway`，并推荐生产使用 Compose 内部 DNS。
- 文档明确推荐 `/opt/ai-workbench`、`/srv/ai-workbench` 或其他部署账号可写的 ASCII 路径。

## 防复发校验

- `git check-attr` 确认所有 Linux 解释文件均为 `eol: lf`，字节检查确认关键文件不含 CR。
- `sh -n scripts/deploy.sh` 返回 0；无 Docker 时在创建 `.env` 前明确退出。
- SnakeYAML 以禁止重复键模式解析 Compose，确认 6 个服务存在，并断言 Redis 映射使用 `REDIS_HOST_PORT`、后端连接使用 `REDIS_PORT`。
- 前端 8 项测试和生产构建通过；后端 10 项测试通过；错题本发布门禁通过。
