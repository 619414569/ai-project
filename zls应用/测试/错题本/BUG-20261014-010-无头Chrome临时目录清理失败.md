# 无头 Chrome 临时目录清理失败

## 原始问题

V1.1 公网页面验收首次执行结束时返回：

```text
Error: EBUSY: resource busy or locked, unlink
C:\Users\ZhuanZ1\AppData\Local\Temp\ai-workbench-e2e-*\en-US-10-2.bdic
```

## 根因

Windows 下调用子进程 `kill()` 后，Chrome 的派生进程可能仍短暂持有拼写词典文件。脚本立即递归删除临时用户目录，清理异常覆盖了此前的页面验收异常或结果，无法判断真实失败阶段。

## 修复

- Windows 下按本次启动的 Chrome 主进程 PID 关闭整个派生进程树，不影响用户已有的浏览器进程。
- 等待浏览器退出后再删除临时用户目录，并对短暂文件锁增加有限次数重试。
- 临时目录清理失败只输出警告，不再覆盖真实网页验收结论。

## 防复发校验

- 浏览器验收脚本必须在页面断言完成后正常输出结构化结果。
- 执行失败时必须保留最初的页面或网络异常，清理异常不得取代原始异常。
- 仅清理本次脚本创建的随机临时目录和进程树，不操作用户浏览器配置或其他 Chrome 进程。

## 2026-10-14 结果输出复测

- 第二次执行时进程树关闭导致控制台没有保留页面失败信息，也没有生成截图。
- 脚本现将通过或失败结果先写入 `E2E_RESULT` 指定的临时 JSON，再关闭浏览器，并在失败结果中保留最初的断言消息。
- 修正后第三次执行明确保留了“等待日志作者选项超时”的原始错误，证明清理阶段不再遮蔽真实失败原因。
