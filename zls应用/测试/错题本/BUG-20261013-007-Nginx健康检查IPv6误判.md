# Nginx 健康检查 IPv6 误判

## 原始问题

- 前端页面和 `/healthz` 从服务器本机及公网访问均返回 HTTP 200，但 Docker 将前端容器标记为 `unhealthy`。
- 健康检查连续输出 `wget: can't connect to remote host: Connection refused`。

## 根因

- Alpine 中 `localhost` 优先解析为 IPv6 地址 `::1`。
- 生成的 Nginx 虚拟主机仅监听 IPv4 的 `80` 端口，健康检查访问 `http://localhost/healthz` 时连接到了未监听的 `::1:80`。

## 修复

- 将前端 Docker 健康检查地址固定为 `http://127.0.0.1/healthz`，使探针与 Nginx 实际监听协议一致。

## 防复发校验

- 容器内访问 `127.0.0.1/healthz` 必须返回 `ok`。
- 前端容器必须进入 `healthy`，不能只以宿主机 HTTP 200 代替容器健康状态检查。
- 服务器本机和公网首页、`/healthz` 均须返回 HTTP 200。
