## 变更类型

部署方式调整：与 `619414569应用` 同机部署，不再自带 PostgreSQL / Redis / RocketMQ 容器。

## 变更摘要

### 1. Compose 编排改造

`docker-compose.yml`

- 项目名由 `ai-scaffold` 改为 `ai-scaffold-chendu`，与 `619414569应用` 的容器名、网络、卷命名空间隔离，避免同机部署时互相重建。
- 删除 `postgres`、`redis`、`rocketmq-namesrv`、`rocketmq-broker`、`rocketmq-volume-init` 五个服务及全部数据卷声明。
- 后端新增外部网络 `shared-network`（`external: true`，默认名 `ai-scaffold_ai-network`），与 `chendu-network` 双挂载；前端只挂 `chendu-network`。
- 端口：前端 `0.0.0.0:81`（`619414569应用` 已占用 80）、后端 `127.0.0.1:8081`（仅回环，供本机排查 actuator，浏览器访问统一走前端 Nginx）。
- RocketMQ 生产者组、消费者组改为 `ai-scaffold-chendu-producer` / `ai-scaffold-chendu-consumer`，避免与 `619414569应用` 争抢同一队列。
- `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`REDIS_PASSWORD`、`JWT_SECRET` 改为 `${VAR:?}`，缺失即失败，不再回落到弱默认值。

### 2. 数据隔离

- 共享 PostgreSQL 实例中使用独立库与独立角色 `ai_scaffold_chendu`，与 `619414569应用` 的 `ai_scaffold` 完全隔离，规避两应用迁移内容不同导致的 Flyway 校验失败。
- 新增幂等建库脚本 `数据/初始化/01_create_database_shared_instance.sql`，通过 psql 变量注入库名、角色名与口令。

### 3. 环境变量模板

`.env.example`

- 新增 `APP_VERSION`、`WEB_BIND_ADDRESS`、`BACKEND_BIND_ADDRESS`、`BACKEND_PORT`、`SHARED_NETWORK_NAME`。
- `WEB_PORT` 改为 `81`，`BACKEND_PORT` 改为 `8081`。
- 删除容器内中间件相关变量（`POSTGRES_*`、`REDIS_PORT` 映射、`ROCKETMQ_*_PORT`），保留共享中间件的连接变量。
- CORS 默认来源改为 `http://localhost:81`、`http://127.0.0.1:81`。

### 4. 部署脚本

新增 `scripts/deploy.sh`：校验 `.env` 是否仍含占位口令、`JWT_SECRET` 长度、共享网络是否存在，随后 `docker compose up -d --build` 并等待后端与前端健康。

### 5. 开发联调

`frontend/vite.config.ts` 的 `/api` 代理默认目标由 `http://localhost:8080` 改为 `http://localhost:8081`，与本机后端映射一致；仍可用 `VITE_PROXY_TARGET` 覆盖。

### 6. 文档同步

`README.md`（同机部署拓扑、启动步骤、访问地址、独立打包示例、上线前检查）、`数据/README.md`（共享实例数据源与建库脚本）、`Makefile`（新增 `config` 目标）。

## 影响范围

| 范围 | 说明 |
| --- | --- |
| 部署方式 | 由自带全套中间件改为只编排前端与后端；同机部署必须先启动 `619414569应用` 的中间件 |
| 端口 | 对外入口由 80 改为 81；后端由 8080 改为回环 `8081` |
| 数据库 | 服务器部署使用独立库 `ai_scaffold_chendu`；本机 `application.yml` 默认库未改动，仍为 `ai_scaffold` |
| 环境变量 | 新增 5 个变量、删除 6 个中间件端口/库变量；旧 `.env` 需按新模板重建 |
| 前端构建 | 仅开发代理默认值变化，产物与接口约定不变 |
| 后端代码 | 无改动 |
| 其他用户目录 | 未涉及；`脚手架/**` 未操作 |

## 回滚方案

| 步骤 | 操作 |
| --- | --- |
| 1 | `docker compose down` 停止 `ai-scaffold-chendu` 栈 |
| 2 | 恢复 `docker-compose.yml`、`.env.example`、`vite.config.ts` 到 `7937adb` 版本 |
| 3 | 若需回到自带中间件模式，按旧编排重新 `up -d --build`，并恢复旧 `.env` 的 `POSTGRES_*` 等变量 |
| 4 | 共享库 `ai_scaffold_chendu` 如已创建，由数据库管理员确认后删除；不删除不影响 `619414569应用` |
