## 变更类型

不兼容裁剪：移除 Spring Security / JWT / 账号体系、Redis、PostgreSQL / Flyway / Flowable、RocketMQ，应用变为零外部中间件依赖的最小骨架。

## 变更摘要

### 1. 移除 Spring Security 与账号体系

- `pom.xml` 删除 security、oauth2-resource-server、spring-security-test
- 删除 `auth/**`、`security/**`、`user/**`、`config/SecurityProperties.java`、`config/DemoUserInitializer.java`
- 删除前端 `LoginView.vue`、`stores/auth.ts`、`api/modules/auth.ts`，路由去掉登录与守卫，`http.ts` 去掉 token 与 401 跳转，`AppLayout` 去掉用户信息与退出登录
- 连同 `config/CorsConfig.java`、`config/CorsProperties.java` 一并删除，不再提供跨域配置（前端经 Nginx 反代，属同源访问）
- `OpenApiConfig` 去掉 bearer 方案；`GlobalExceptionHandler` 去掉认证异常处理

> 影响：所有接口不再鉴权。

### 2. 移除 Redis

删除 `demo/cache/**`、`spring-boot-starter-data-redis`、`spring.data.redis`，前端去掉缓存面板。

### 3. 移除 PostgreSQL / Flyway / JDBC 与 Flowable

删除 `resources/db/**`、`resources/processes/**`、`demo/workflow/**`、`数据/初始化/**`，`pom.xml` 去掉 jdbc、postgresql、flyway、flowable，`数据/README.md` 改为无持久化说明。

### 4. 移除 RocketMQ

仅删除配置会让 `@RocketMQMessageListener` 的 `topic`、`consumerGroup` 与生产者组占位符无值，导致启动失败，因此整块移除：

- `pom.xml` 删除 `rocketmq-spring-boot-starter` 与版本属性
- 删除 `demo/messaging/**`（发布器、监听器、控制器、降级实现）、`config/IntegrationProperties.java`
- 删除前端 `IntegrationView.vue` 与相关菜单、接口方法、类型定义
- `docker-compose.yml` 不再需要外部网络 `ai-scaffold_ai-network`，只保留内部 `chendu-network`

### 5. 配置与部署

- `application.yml` 只剩一项 `spring.application.name`（嵌套写法）；端口、日志、Jackson、Swagger、info、健康探针、CORS 全部使用框架默认值或不启用
- `docker-compose.yml` 精简为 2 个服务：去掉 `.env` 变量插值、healthcheck、健康条件依赖与前端构建参数，端口与镜像名直接写死
- 网络改为外部引用 `619414569应用` 的 `ai-scaffold_ai-network`（不再新建网络）；项目名 `notebook`，服务名 `notebook-backend`/`notebook-frontend`，避免与其 `backend`/`frontend` 别名冲突
- 删除 `.env.example`；`scripts/deploy.sh` 只保留 docker 与 jar 两项校验
- `scripts/deploy.sh` 去掉共享网络与业务口令校验，保留 `.env` 换行检查，并新增 jar 存在性检查
- `backend/Dockerfile` 改为单阶段：镜像只拷贝宿主机产出的 `target/ai-scaffold-backend.jar`，不再在 Docker 内跑 Maven；`.dockerignore` 只放行该 jar
- 构建链随之调整：`docker-compose.yml` 后端改为引用 `notebook-backend:local`（不参与 compose build），`scripts/deploy.sh` 先 `docker build` 再启动，`Makefile` 新增 `backend-jar`、`backend-image` 目标
- `frontend/Dockerfile` 同步改为单阶段：本地 `npm install && npm run build` 产出 `dist/`，镜像只托管 `dist` 与 nginx 模板，不再安装 Node；`frontend/.dockerignore` 排除 `node_modules`、`src`；`deploy.sh` 增加 `dist/index.html` 校验；`Makefile` 新增 `frontend-dist` 目标
- `README.md` 重写为「零外部依赖」部署说明

### 6. 新增内存 CRUD 接口

`demo/item/`：

- `Item`：`id`、`title`、`content`、`createdAt`、`updatedAt`
- `ItemService`：`ConcurrentHashMap` 内存存储，提供 `list`、`get`、`create`、`update`、`delete`
- `ItemController`：`/api/v1/items` 的 `GET`（`?deleted=true` 查回收站）、`GET /{id}`、`POST`（返回 `201`）、`PUT /{id}`、`DELETE /{id}`（移入回收站）、`POST /{id}/restore`、`DELETE /{id}/permanent`；`title` 必填 ≤100，`content` ≤2000，`id` 不符合 `[A-Za-z0-9-]{1,64}` 直接 400
- 删除采用两段式：移入回收站（`deleted=true` 标记）而非直接移除；回收站中条目不可编辑（`409`）、不可重复移入（`409`），只有彻底删除才从 `ConcurrentHashMap` 移除
- `ItemServiceTest`：10 个用例覆盖新建、更新、列表排序、移入回收站、恢复、彻底删除与三类冲突分支

数据不落库，进程重启即清空；后续接数据库时替换 `ItemService` 实现即可，接口契约不变。

### 7. 新增手账页（前端接入 CRUD）

参考本地原型 `晨间记录`（三栏：图标栏 + 分类侧栏、列表、编辑区）：

- `views/NotebookView.vue`：暖色主题三栏布局；左侧分类（所有日记 / 今天 / 本周 / 回收站，带数量统计），中间搜索框 + 「写点什么」+ 条目列表，右侧编辑区（标题、正文、保存、删除、字数统计）
- `api/modules/items.ts`：`list(deleted)` / `get` / `create` / `update` / `trash` / `restore` / `purge`，全部走后端接口
- 路由：`/` 改为手账页，原「运行概览」移到 `/status`，`AppLayout` 菜单补充两项
- 交互细节：新建为空表单，保存后自动选中；编辑保存后刷新列表；删除对齐原型的「先移入回收站」，无确认弹窗、直接执行并 toast 提示；回收站条目只读，可「恢复」或「彻底删除」，列表卡片内也提供「恢复」链接；搜索与今天/本周筛选在前端计算
- 多选：每条记录左侧勾选框（`Set<id>` 维护选中态），选中后列表上方出现多选栏（全选 / 已选 N 篇 / 删除 / 取消）；删除按视图分流，正常视图批量移入回收站、回收站视图批量彻底删除

| 范围 | 说明 |
| --- | --- |
| 接口 | 鉴权相关接口全部删除；新增 `/api/v1/items` 增删改查与回收站接口（`?deleted=`、`/restore`、`/permanent`） |
