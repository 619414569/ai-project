# 2026-10-19 切换空库后构建因 Flowable 表缺失失败

| 项 | 值 |
| --- | --- |
| 编号 | BUG-20261019-004 |
| 日期 | 2026-10-19 |
| 严重度 | 中 |
| 状态 | resolved |
| 环境 | 本机开发环境，PostgreSQL 14.24，数据库 `ai_scaffold` |
| 影响 | `mvn -B clean package` 在测试阶段失败，无法产出 JAR |

## 摘要

把 `chendu应用` 的数据库连接从已有库 `brilliant-idea` 切换到新建的空库 `ai_scaffold` 后，
`mvn -B clean package` 在测试阶段失败：`AuthIntegrationTest` 的 10 个用例全部因
`Failed to load ApplicationContext` 报错。

## 原始错误

```text
Caused by: org.apache.ibatis.exceptions.PersistenceException:
### Error querying database.  Cause: org.postgresql.util.PSQLException: 错误: 关系 "act_ge_property" 不存在
### The error may exist in org/flowable/common/db/mapping/entity/Property.xml
```

外层为 `IllegalStateException: Failed to load ApplicationContext`，依赖链为
`workflowController` → `workflowService` → `runtimeServiceBean` → `processEngine`。

## 根因

集成测试把 `flowable.database-schema-update` 置为 `false`，不会自动建 Flowable 表，
依赖目标库中已存在 `act_*` / `flw_*` 表。原 `brilliant-idea` 库的这些表是此前应用以
`flowable.database-schema-update: true` 启动时建好的；新建的 `ai_scaffold` 是空库，还没有，
Flowable 引擎初始化查询 `act_ge_property` 即失败。

问题不在代码，而在新库的初始化顺序：必须先由应用以默认配置启动一次完成 Flowable 建表，
之后测试才能以 `database-schema-update: false` 运行。

## 修复

1. `mvn -B clean package -DskipTests` 先产出 JAR；
2. 以默认配置（不覆盖 `flowable.database-schema-update`）启动应用一次：Flyway 建
   `app_setting` / `workbench_user`，Flowable 建 38 张表（实测 `act=30`、`flw=8`），
   `DemoUserInitializer` 播种 `admin` 与 `dcy`；
3. 再次 `mvn -B test`，`Tests run: 21, Failures: 0, Errors: 0`，`BUILD SUCCESS`。

## 可重复回归用例

1. 对任意新建的空库，先以默认配置启动应用一次，确认 `act_ge_property` 存在；
2. 再执行 `mvn -B test`，期望 21/21 通过。

## 防复发

`数据/README.md` 的建库脚本章节已注明：脚本只建角色和库，表由应用首次启动时的
Flyway 与 Flowable 创建，新环境必须先启动应用一次再执行测试。
