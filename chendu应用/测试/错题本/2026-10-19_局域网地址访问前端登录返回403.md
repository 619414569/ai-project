# BUG-20261019-002

| 项 | 值 |
| --- | --- |
| 编号 | BUG-20261019-002 |
| 日期 | 2026-10-19 |
| 严重度 | 中（局域网或 127.0.0.1 访问时登录完全不可用） |
| 状态 | resolved |
| 模块 | `backend` 安全认证（`SecurityConfig`、`CorsProperties`） |
| 环境 | 本地开发（Vite dev server 绑定 `0.0.0.0:5173`） |

## 摘要

通过 `http://<局域网IP>:5173` 访问前端时，登录请求返回 `403`，与用户名密码是否正确无关。

## 原始错误

浏览器请求 `POST /api/v1/auth/login` 返回：

```text
HTTP 403 Forbidden
```

服务端判定为 `Invalid CORS request`，请求未进入 Controller。

## 根因

前端 dev server 在 `frontend/vite.config.ts` 中绑定 `host: '0.0.0.0'`，因此可通过三种地址访问：`localhost`、`127.0.0.1`、局域网 IP（如 `192.168.62.111`）。

而后端 CORS 只做了**精确来源匹配**：

```java
configuration.setAllowedOrigins(properties.allowedOrigins());
```

`app.cors.allowed-origins` 默认仅含 `http://localhost`、`http://localhost:5173`（后续补齐了 `127.0.0.1` 两项）。浏览器按实际访问地址回传 `Origin`，局域网地址不在白名单中，被 CORS 层直接拒绝，返回 403。

**特征**：用 `localhost` 访问正常，换成 `127.0.0.1` 或局域网 IP 即 403。因 403 出现在 Controller 之前，容易被误判为「认证失败」而反复排查账号口令。

## 修复

1. `CorsProperties` 增加可选的模式来源配置项：

```java
public record CorsProperties(@NotEmpty List<String> allowedOrigins, List<String> allowedOriginPatterns) {
    public CorsProperties {
        allowedOrigins = List.copyOf(allowedOrigins);
        allowedOriginPatterns = (allowedOriginPatterns == null) ? List.of() : List.copyOf(allowedOriginPatterns);
    }
}
```

2. `SecurityConfig.corsConfigurationSource` 同时设置模式来源：

```java
configuration.setAllowedOrigins(properties.allowedOrigins());
// Exact origins cannot cover the Vite dev server once it is reached through
// 127.0.0.1 or a LAN address, so patterns are supported as well.
configuration.setAllowedOriginPatterns(properties.allowedOriginPatterns());
```

3. `application.yml` 增加默认值（回环地址 + RFC1918 私有网段）：

```yaml
app:
  cors:
    allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost,http://localhost:5173,http://127.0.0.1,http://127.0.0.1:5173}
    allowed-origin-patterns: '${CORS_ALLOWED_ORIGIN_PATTERNS:http://localhost:*,http://127.0.0.1:*,http://192.168.*:*,http://10.*:*,http://172.1[6-9].*:*,http://172.2[0-9].*:*,http://172.3[01].*:*}
```

4. 同步更新 `.env.example` 与 `README.md` 的说明。

`CorsConfiguration#checkOrigin` 会先做精确匹配再做模式匹配，两者可共存；模式匹配不会与 `allowCredentials(true)` 冲突（区别于 `*`，后者在 credentials 开启时会被拒绝）。

## 可重复回归用例

自动化测试已固化：`backend/src/test/java/com/aiproject/scaffold/auth/AuthIntegrationTest.java` 的 `allowedOriginsAreAccepted`（白名单内放行并回显来源头）与 `unknownOriginIsRejected`（白名单外 `403`，不回显来源头，响应体为 `Invalid CORS request`）。执行方式见 [测试记录](../测试记录/2026-10-19_登录与跨域回归测试记录.md)。

前置：后端已启动，前端 dev server 已启动，取本机局域网 IP 替换 `<LAN_IP>`。

```powershell
$origins = @(
  "http://localhost:5173",
  "http://127.0.0.1:5173",
  "http://<LAN_IP>:5173",
  "http://evil.example.com"
)
foreach ($o in $origins) {
  try {
    $r = Invoke-WebRequest -Uri "http://localhost:8080/api/v1/auth/login" -Method Post `
           -Body '{"username":"admin","password":"Admin@123456"}' `
           -ContentType "application/json" -Headers @{ "Origin" = $o } -UseBasicParsing
    "$o -> HTTP $($r.StatusCode)"
  } catch { "$o -> HTTP $([int]$_.Exception.Response.StatusCode)" }
}
```

**期望结果**：

| Origin | 期望 |
|---|---|
| `http://localhost:5173` | `200` |
| `http://127.0.0.1:5173` | `200` |
| `http://<LAN_IP>:5173` | `200` |
| `http://evil.example.com` | `403`（仍需被拒绝） |

**修复前的实际结果**：`http://192.168.62.111:5173` 返回 `403`。

## 防复发措施

- 前端 dev server 一旦绑定 `0.0.0.0`，后端 CORS 就必须同时支持模式来源，不能只依赖精确白名单。
- 排查登录异常时，先用带/不带 `Origin` 的请求对比，区分 CORS 拒绝（403，未进 Controller）与凭据错误（401，来自 `GlobalExceptionHandler`）。
- 公网部署时必须显式覆盖 `CORS_ALLOWED_ORIGINS` 与 `CORS_ALLOWED_ORIGIN_PATTERNS`，不要沿用开发默认值。
