# ai-project
1、本项目为小组内研发AI功能专用仓库
2、每个人负责各自的模块，每周至少一次更新，每周定时提交更新日志
3、可以多人组队开发同一个模块，也可以依赖于框架独立设计自己的功能模块
4、基础功能框架：
  a.框架底座
  b.登录模块（用户名 + 密码）
  c.日志模块
  d.工作台模块
5、每个人至少选一个市面上的中高级的智能体
6、前三个月可以进行工具类、统计类的应用开发，三个月后每个人必须进入Agent开发阶段
7、个人提交记录统一维护在[提交日志](./提交日志/README.md)目录

## 目录边界

- [`脚手架`](./脚手架/README.md) 是团队通用底座，只允许在明确的脚手架维护任务中修改。
- `{username}应用` 是个人应用一级目录，应用源码、原型、测试和数据均维护在该目录内。
- 任何应用功能开发、缺陷修复或版本发布都不得新增、修改、删除或重命名 `脚手架/**` 下的文件。
- 应用确需新增底座能力时，必须另行发起脚手架维护任务并单独提交，禁止与应用代码混合提交。

## 验收与提交规则

- 自动化测试、构建、部署和回归通过只代表技术检查完成，不自动代表用户验收通过。
- 只有项目负责人在对话中单独输入完整口令 `本次验收通过`，当前变更范围才能确认为验收通过。
- 收到口令后，验收通过的代码可以直接提交并推送到 Git；没有收到口令时不得将最终验收结论标记为通过，也不得按“已验收”提交。
- 口令只确认当时列明且已完成测试的变更范围。确认后若代码、配置、数据脚本或测试结论再次变化，验收状态必须恢复为待确认并重新获取口令。
